# PROMPT_FLOW — 3시간 안에 끝나는 짧은 프롬프트 13개

STAGE_PROMPTS가 "단계별 지시 모음"이라면, 이 문서는 **처음부터 끝까지 한 줄로 이어지는 실전 순서**다.
원칙은 **프롬프트 하나 = 한 단계 + 멈춤**. 큰 지시 몇 번보다 짧은 지시 여러 번이 기록·검증·재개에 모두 유리하다.

## 매번 넣을 다섯 문장

1. **범위**: "○○만 하고 나머지는 고치지 마."
2. **멈춤**: "끝나면 멈춰." / "바꿀지 말지 확인받고 멈춰."
3. **내 예상**: "내 예상은 ○○야. 실제와 비교하고, 틀렸으면 틀렸다고 써."
4. **근거·대안**: "왜 그렇게 했어? 근거와 대안 2개를 실제로 돌려서 비교해."
5. **이해 확인**: "내가 이해한 구조는 ○○야. 틀린 부분만 짚어."

D번호(담당자 결정)는 정책이 걸린 지시마다 인용한다.

## 속도 요령

- **Codex가 도는 동안 다음 프롬프트를 쓰거나 담당자와 대화한다.** 기다리는 시간이 가장 큰 낭비다.
- 문서·기록 단계는 추론 강도를 낮추고, 알고리즘·디버깅만 높인다. 최고 강도는 같은 실패가 반복될 때만 쓴다.
- 서버를 띄우는 지시에는 항상 "확인 후 끄고 포트가 비었는지 확인"을 붙인다. 켜 둔 서버 때문에 다음 단계가 멈출 수 있다.
- 결과 문서는 "맨 위 3줄 요약 + 4칸 이하 표"를 요구한다. 읽는 시간이 절반으로 준다.

## "내 예상"이 막힐 때

데이터 지도가 나오면 30초 안에 세 가지만 적는다. 틀려도 된다. 틀린 기록은 REVIEW의 "예상 vs 실제"가 된다.
1. 지금 지표 → 개선하면 대충 얼마
2. README에 계산법이 없는 숫자 열 하나 → "○○ × 상수일 것"
3. 날짜·시간이 넘어가는 경계 하나

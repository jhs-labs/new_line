# QUICKCARD — 현재 단계만 보기

**묻기 → 정하기 → 준비 → 한 번 실행 → 검사 → 사용자 확인 → 전달.**

## 시작 0~5분 — 이 순서로

0. 키트는 프로젝트 폴더 **밖**에 받는다: `git clone <키트 주소> /tmp/new_line`. 프로젝트 폴더 안에 받으면 전달물·commit·Codex 검색에 섞인다.
   `pwd; ls -a; date` — 프로젝트 폴더가 홈(`.bashrc`·`.config`가 보임)인지, 서버 시각이 UTC인지 확인한다.
1. **한 번에:** `python3 /tmp/new_line/install.py --target . --start`
   .gitignore(`.codex/` 로그인 정보·셸 설정 제외) → `git init`(없을 때만) → `init: 프로젝트 원본` commit → 키트 설치 → work 양식 → `chore: new_line 설치` commit.
   - 상위 폴더가 이미 Git이면 멈춘다. 프로젝트 폴더를 다시 확인한다.
   - 모르는 숨김 파일이 보이면 commit 전에 멈춘다. 비밀이면 .gitignore에 넣고, 프로젝트 파일이면 `--allow-hidden`.
   - 이미 commit이 있으면 원본 commit은 건너뛰고 키트 파일만 commit한다.
   - 단계별로 하려면 [GIT](GIT.md)의 `--gitignore-only` → init commit → install 순서.
2. Codex 업데이트 안내가 뜨면 건너뛴다. `npm install -g`·`sudo` 설치를 하지 않는다.
3. **프로젝트 폴더에서** Codex를 연다. 상위 폴더에서 열면 AGENTS.md가 로드되지 않는다.
4. "지금 적용 중인 AGENTS.md 규칙 3개만 말해 줘"로 로드를 확인한다. 못 말하면 다시 연다.
5. state.md에 작업 폴더·Git 루트·AGENTS 로드 확인을 적는다.
6. 사전 점검·시작 때 Codex 모델과 effort(가능한 최고값)를 확인한다.
7. 포트: README에 정해져 있으면 그 포트, 없으면 **3000**(흔한 개발 서버 포트). 서버는 0.0.0.0에 띄우고 미리보기로 화면이 보이는지 바로 확인한다.

**새 세션을 열 때마다 첫 메시지:** "handoff 요약만 읽고 STATE와 다음 3행동을 한 줄로 말해. 이 세션은 [범위]만 맡는다. 기록 파일은 고치지 마(기록 담당 세션이면 이어받기 확인 칸에 남겨)."
**세션 끊는 시점은 미리 정한다: 80분·140분**에 handoff 요약 갱신 → 새 세션 → 되말한 요지를 `이어받기 확인:` 칸에. 옆 창에 읽기 전용 감시 세션(진행률·남은 시간·빈칸 점검, 합의문·전달 직전 코드 교차 검증)을 둘 수 있다.
여러 세션을 돌리면 기록 파일(decisions·requirements·state·handoff)을 고치는 세션은 하나만 정한다.

처음부터 끝까지 이어지는 짧은 프롬프트 13개는 [PROMPT_FLOW](PROMPT_FLOW.md). 프롬프트 하나 = 한 단계 + 멈춤.

매 프롬프트 전 30초·체크포인트마다 2분은 [SELFCHECK](SELFCHECK.md)로 결과·방향·이해·인계 빈칸을 확인한다.

| STATE | 남길 최소 근거 | 선택 지시 |
|---|---|---|
| DISCOVERY | 제약·공개 입력·질문/답 원문·Unknown | STAGE_PROMPTS의 DIS |
| CONTRACT | 사람 확인 범위·REQ 합격 문장·단계 계약 | CON |
| SCAFFOLD | 기존 파일/함수↔실행 명령, 작은 입력·기대값 | SCA |
| E2E_V0 | 실제 입력→출력·작은 기대값 검사·첫 피드백 요청 | E2E |
| VERIFY | P0·경계/회귀·실제 로그·남은 위험 | VER |
| ACCEPT | 사용자 피드백/미응답·최종 회귀·필수 문서·한계 | ACC |
| SUBMIT | 전달 위치 fresh run·필수 파일·실제 인도 확인 | SUB |

## 단계별 체크리스트 (SCAFFOLD부터) — 단계를 넘기기 전에 확인

| 단계 | 참고 시각 | 끝 조건 (모두 ✓면 넘긴다) |
|---|---|---|
| SCAFFOLD | ~45분 | 실행 명령 하나로 서버가 뜸 · `/health` 200 · API가 README 형식(빈 값이라도) · **config.json에 지금까지 합의값 + D-ID** · 테스트 1개 · 서버 끄고 포트 비움 · 커밋 |
| E2E_V0 | ~80분 | 실제 입력→출력이 한 번 이어짐 · **파라미터 없이 불러도 합의값으로 결과** · 실행 전 "내 예상" 한 줄과 실제 비교 · 커밋. **80분이 넘으면 분석이 덜 끝나도 v0부터 끝낸다** |
| VERIFY | ~140분 | P0 REQ마다 테스트 먼저 → 실패 확인 → 구현 → 통과 → `REQ-xxx` 커밋 · 리스크 재현 테스트 · "내가 이해한 구조" 확인 2회 · **D ↔ 코드 대조에서 빠진 D 0개** · 안 묻고 정한 것 보고. **140분에 새 기능 동결** |
| ACCEPT | ~165분 | 결과를 담당자에게 보여 주고 반응 기록 · README가 요구한 제출물 전부 · REVIEW(예상 vs 실제 3건, 틀릴 수 있는 경우 3개를 지점→위험·파급→다음 계획으로, 비교표) · problem 템플릿 칸 유지 · handoff 요약 갱신 · 커밋 |
| SUBMIT | ~180분 | 새 터미널에서 HOW_TO_RUN대로 실행 → state GATE3에 명령·결과 · HOW_TO_RUN에 오류 대처 절 · 세션 기록 zip(로그인 정보·숨김 파일 제외) · `git status` 깨끗 · 최종 커밋(총 6개 이상) |

- **P0만 하고 전달해도 된다.** P0 = 빠지면 결과가 틀리거나 쓸 수 없는 것(API 형식·합의값 기본값·결과를 크게 바꾸는 리스크·요청자의 제일 큰 고민·확정 규칙). 시간이 모자라면 P0 하나보다 필수 제출물이 먼저다.
- P1을 안 했으면 decisions에 "안 한 것·이유·다음 할 일"을 한 줄 남긴다.
- 영향이 작은 세밀한 분석(분포 쪼개기 등)은 v0 뒤로 미룬다. analysis.md의 `영향:` 칸이 비는 분석은 하지 않는다.
- 사람이 직접 할 것 하나: VERIFY에서 "내가 이해한 구조: 읽기 → … → 출력, 정책 값은 config.json. 틀린 부분만 지적해"를 두 번 말한다.

## 네 가지를 연결하기

질문/답 **Q-ID** → 선택/이유 **D-ID** → 합격 기준 **REQ-ID** → 실제 명령·결과·근거.
정책 승인 / 구현 검사 / 사용자 결과 수용의 O/X를 따로 쓴다. 파일이 있다는 사실을 승인·실행 성공으로 바꾸지 않는다.

데이터는 **읽기→정규화→정제→판정→순위/집계→표시**로 흐른다. 7 STATE와 별개이고 파일 6개를 강제하지 않는다.
정상 대표·격리 원본·중복 원본이 배타적일 때만 같은 파일의 원본 레코드 보존식을 쓴다. 경고를 정상 건수에 다시 더하지 않는다.

## 인터뷰 (DISCOVERY)

- 처음 3분은 해법 단어(자동화·AI·화면)를 꺼내지 않는다.
- 순서: 실제 사례 → 지금 우회 방법 → 숫자(빈도·시간·실패 비용) → 누가 쓰고 누가 결정하나 → 경계·예외.
- 성공 기준은 **숫자 + 현재값 + 측정처**로 적는다 (예: 주 반나절 → 10분, 측정: 감사 준비 시간).
- README에 문제가 자세히 적혀 있으면 다시 캐지 말고 갈림길(경계·예외·충돌·결정권자)만 확인하고 빨리 만든다.

## 나중에 설명할 때 (AI 없이 내 말로)

결정은 나중에 다시 설명해야 할 때가 많다. 질문 유형별 틀:
- **왜 이렇게 했나** → 결론 → 근거(Dn·담당자 답·데이터) → 안 했으면 생기는 일.
- **장애가 나면·어디서 틀리나** → ① 약점 지점(파일·함수·데이터·경계값) ② 왜 위험한지·어디까지 번지는지 ③ 다음에 검증·개선할 것.
숫자는 기억나는 것만, 모르면 "확인 못 함"이라고 쓴다. REVIEW·handoff가 설명의 근거다.

## 독립 work 후보 도구

```sh
python fde/kit/preflight.py --port 3000
python fde/kit/init_work.py
python fde/kit/evaluate.py
python fde/kit/promote.py --report latest
python fde/kit/bundle.py
python fde/kit/status.py
python fde/kit/status.py --intent   # Q→D→REQ→commit 기록 빈칸
```

빈 checks는 거절된다. 지정 src/가 있는 앱에는 자체 검사·전달 구조를 유지한다. work 밖 파일은 ZIP에 자동 포함되지 않는다.

## 3시간 집중 세션 예시 — 실제 일정이 우선

0~15 입력·질문 / 15~30 합의·검사 계획 / 30~45 최소 실행 / 45~115 P0 / 115~140 사용자 흐름·위험 / 140~155 회귀·설명 / 155~170 fresh run·인계 / 170~180 전달 확인.
80분 구조 동결·140분 새 기능 동결·170분 최종 전달 준비는 참고 경계다. 안전·핵심 오류·확인된 필수 수정은 이유를 남기고 최소 변경·재검증한다. 선택 기능·장식부터 줄인다.
같은 실패 3회면 원인·작은 재현·대안 2개를 확인한다. 긴 작업은 handoff의 다음 3행동으로 재개한다. 전달 규칙·허용 도구·네트워크·승인 절차는 실제 프로젝트를 따른다.

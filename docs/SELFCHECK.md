# SELFCHECK — 네 가지 관점으로 작업 점검하기

AI와 함께 작업하면 "했다"와 "남았다"가 쉽게 어긋난다. 이 점검표는 **대화·터미널·git·문서에 실제로 남은 것**을 기준으로 빈칸을 찾는다.
표기: **[결과]** 실제로 돌고 맞는가 · **[방향]** 목표·범위·검증을 내가 통제했나 · **[이해]** 왜 이렇게 됐는지 내가 설명할 수 있나 · **[인계]** 다른 사람이 이어받을 수 있나.
사용법: ① 프롬프트 보내기 전 30초(1절) ② 체크포인트마다 2분(2절) ③ 마무리 전 관점별 O/X(3절). 빈칸은 다음 프롬프트에서 채우고, 체크를 채우려고 기록을 지어내지 않는다.

## 0. 어디에 힘을 줄까

| 관점 | 흔한 빈틈 | 처방 |
|---|---|---|
| **방향** | 큰 지시 한 번에 맡기고 결과만 받음 | **매 프롬프트를 같은 틀로**: 범위·근거 D·내 예상·멈출 조건·증거 |
| **이해** | 결과를 읽지 않고 "좋아, 다음" | 실행 전 **내 예상**, 직접 읽고 **내 말로 설명**, "**왜·대안**" 질문, 반박을 대화에 남긴다 |
| **결과** | 마지막에 몰아서 기능 추가 | P0 정확성·건수 보존·보안·fresh run. 후반에는 새 기능 금지 |
| **인계** | 문서를 마지막에 한 번에 씀 | 체크포인트마다 handoff 갱신, **새 세션이 문서만으로 이어가는지** 한 번 확인 |

## 1. 매 프롬프트 — 보내기 전 30초

| 점검 | 무엇을 넣나 | 프롬프트 문장 예 |
|---|---|---|
| 범위 | 한 REQ·한 METHOD 단계만, 손대지 말 파일 명시 | `[REQ-014 / METHOD ③]만. report.js 외 수정 금지` |
| 완료 모습 | 출력 형태·대상·기대값 | `센서 A가 조치, 근거 시각 표시` |
| 근거 | 정책이면 D-ID 인용, 없으면 질문으로 | `D4·D9 기준으로` |
| 내 예상 | 숫자·순위·깨질 테스트 중 하나 | `내 예상: 확인 4건, A만 조치` |
| 멈출 조건 + 증거 | 테스트 먼저→실패 확인→구현→전체 테스트·exit code | `결정표에 없는 규칙이 필요하면 멈추고 질문 초안` |
| 제약 | 스택·외부 전송·금지 도구·전달 경로 | `표준 라이브러리만, 0.0.0.0 바인딩 유지` |

받은 뒤 30초:
- [ ] **[이해]** 예상과 결과를 대조했다. 다르면 METHOD 단계 번호로 원인을 물었다
- [ ] **[이해]** `git diff --stat`으로 범위를 보고 핵심 함수 하나를 직접 읽었다. 이해를 한 줄로 확인받았다
- [ ] **[이해]** 새 기준값·방식이 나오면 "왜 이 값인가, 대안 1~2개와 결과 차이"를 물었다
- [ ] **[이해]** 결정과 다른 구현이면 D-ID를 근거로 반박하고 되돌렸다
- [ ] **[방향]** 새 담당자 답은 같은 응답에서 interview Q-ID → decisions D-ID로 기록했다
- [ ] **[결과]** REQ가 통과하면 `REQ-xxx: METHOD ④ 요약 (Dn)`으로 commit했다

## 2. 체크포인트 — 3시간 세션 예시

### 0~5분 시작
- [ ] **[방향]** Git 루트 확인 → `init: 프로젝트 원본` commit → install.py → init_work.py ([GIT](GIT.md))
- [ ] **[방향]** 프로젝트 폴더에서 Codex 시작, AGENTS 규칙 3개를 말하게 해서 로드 확인
- [ ] **[방향]** 금지 도구·외부 전송·전달 경로·실행 방법을 problem 제약과 state에 기록

### 15분 DISCOVERY 끝
- [ ] **[방향]** problem: 사용자·해결할 문제·측정 가능한 성공 기준, 만들 것·만들지 않을 것·제약·Unknown
- [ ] **[이해]** 데이터를 직접 열어 함정 후보를 내가 먼저 적고, AI 분석(data_map)과 비교
- [ ] **[방향]** 질문 3~5개를 보내고 답 원문은 interview에

### 30분 합의
- [ ] **[방향]** skeleton ①~⑥ 행마다 입력→출력·함정·D-ID·REQ
- [ ] **[방향]** requirements REQ마다 P0/P1/P2·합격 문장·검증 명령·근거 D
- [ ] **[결과]** 담당자 범위 승인과 시각을 state GATE1에 기록, commit

### 45분 첫 결과
- [ ] **[결과]** 실제 입력→실제 출력이 한 번 끝까지 나옴
- [ ] **[이해]** 실행 전 예상을 대화에 남기고 결과와 대조
- [ ] **[이해]** "내가 이해한 구조: ①…⑥, 정책 값은 config" 한 줄을 확인받음
- [ ] **[인계]** handoff 첫 작성: 목표·STATE·실행 명령·다음 3행동

### 80~90분 구조 동결
- [ ] **[결과]** 단계별 함수, 판정·순위는 순수 함수, 정책 값은 config(+D 연결)
- [ ] **[이해]** 입력→파일:함수→정책→출력을 **내가** 추적해 decisions에 기록
- [ ] **[인계]** handoff·state 갱신

### 115분 검증 끝
- [ ] **[결과]** P0 REQ 전부 통과, REQ별 commit
- [ ] **[결과]** 정답 사례·경계·회귀·건수 보존식(배타 분류의 합 = 입력) 통과
- [ ] **[결과]** 오류 행을 버리지 않고 보여 줌, XSS(textContent)·하드코딩 경로·바인딩·비밀값 점검
- [ ] **[이해]** 주요 기준값마다 "왜·대안"을 물은 흔적이 있다

### 140분 새 기능 동결
- [ ] **[방향]** 새 요청을 설정 변경 / 단계 내부 / 경계 변경으로 분류해 반영·보류, 새 D와 "대체됨→Dn"으로 기록
- [ ] **[결과]** 읽기 전용 감사 1회: 합의문↔코드↔테스트 대조
- [ ] **[이해]** 한계·장애 시나리오를 내가 먼저 쓰고 AI는 보완만
- [ ] **[결과]** 문서 주장 감사(STAGE_PROMPTS ACC-9): 근거 없는 문장·대체된 D의 옛 표현 0개

### 155분 fresh run
- [ ] **[결과]** 새 터미널에서 README_RUN 그대로 실행, 명령·exit code·HTTP 응답 기록
- [ ] **[결과]** 요구된 문서 이름 그대로, 선택 이유·검증·한계 포함
- [ ] **[이해]** 예상 질문 5~6개에 내 말로 답: "왜"는 결론→근거→안 했으면, "장애"는 약점→파급→다음 검증
- [ ] **[인계]** 새 세션에서 "handoff·README_RUN만 읽고 현재 상태와 다음 행동 3개를 말해 줘" → 틀린 곳만 문서 보강

### 170분 전달 직전
- [ ] **[결과]** 전달 경로·파일명·저장 상태 확인
- [ ] **[이해]** 6줄 설명 연습: 구조(①~⑥), 가장 큰 결정(Dn·대안·결과 차이), 어디서 깨지나, 남은 한계
- [ ] **[인계]** handoff 최종: 완료 증거·미결 D·알려진 한계·다음 3행동, 마지막 commit

## 3. 마무리 전 관점별 O/X

| 관점 | 확인할 것 | 남길 근거 | O/X |
|---|---|---|---|
| 결과 | 돌고, 맞고, 새지 않나 | 테스트 출력, 보존식, fresh run 기록, 보안 점검 | |
| 방향 | 목표·범위·검증을 내가 정했나 | problem 성공 기준, Q→D→REQ 연결, 테스트 먼저 흔적, 프롬프트 틀 반복 | |
| 이해 | 왜·어떻게·어디서 깨지는지 아나 | 프롬프트 속 내 예상, 구조 되말하기, 왜·대안 질문, 반박·되돌림 | |
| 인계 | 남이 이어받을 수 있나 | handoff 요약, README_RUN, 이어받기 확인 기록 | |

## 4. 피할 행동
- **[방향]** "알아서 다 만들어 줘" 한 방 프롬프트, 담당자 답 요약·지어내기, 미응답을 승인으로 기록
- **[방향·결과]** 테스트가 실패하자 테스트나 기준을 고치게 두기
- **[결과]** 데이터 행 조용히 삭제, 후반 새 기능, 전달 경로 착오, 서버를 켜 둔 채 다음 단계 진행
- **[이해]** 결과를 읽지 않고 "좋아, 다음" 반복, AI 용어를 이해 없이 문서에 옮기기
- **[인계]** handoff를 마지막에 몰아 쓰기, 문서와 실제 코드·명령이 다름
- **[결과·이해]** src에 없는 규칙을 문서에 씀, 바뀐 결정의 옛 문장 잔존, 실행하지 않은 숫자·통과 주장

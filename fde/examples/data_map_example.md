# data_map 예시 — 가상의 회의실 예약 데이터

## 한눈에 (3줄 요약)
- **지금**: 4주 동안 예약 3,120건, 회의실 평균 사용률 **41%**. 같은 시간 겹침 예약 6건.
- **함정 1**: `fee_krw`(사용료) 계산법이 README에 없음 → 역산하니 **시간당 단가 × 1.1**(부가세)과 전부 일치.
- **함정 2**: 자정을 넘기는 야간 예약 38건은 **시작한 날** 소속인데, `end_at` 날짜는 다음 날.

## 파일 한눈에
| 파일 | 종류 | 행 수 | 연결 키 |
|---|---|---:|---|
| rooms | 기준 | 24 | room_id |
| employees | 기준 | 410 | emp_id |
| bookings | 기록 | 3,120 | booking_id |
| cancel_requests | 요청 | 215 | booking_id |

## 파일별 메모
- **rooms** (회의실 24개): 정원·시간당 단가. `room_id`는 `R07`처럼 앞자리 0 → 문자열 유지.
- **employees** (직원 410명): 부서·사번. 이름은 겹침 → **사번으로만** 연결.
- **bookings** (예약 3,120건): 한 줄 = 예약 한 건. `start_at`·`end_at`에 시간대 표기 없음. 참석 인원은 **합계만** 있고 명단 없음.
- **cancel_requests** (취소 신청 215건): 이미 `bookings.status`에 반영된 것과 아닌 것이 섞임 → 또 빼면 이중 계산 위험.

공통: 빈 칸 0개, 중복 키 0개, 끊긴 연결 0개.

## 0이 아닌 숫자만
- 현재 지표: 평균 사용률 41%, 예약당 평균 참석 4.2명
- 이상한 값: 정원 초과 예약 3건(정원 8명 방에 11명), 겹침 예약 6건
- 중복·끊긴 연결: 모두 0

## 함정 후보 — 함정 — 본 것 → 위험 → 처리
1. **계산법 없는 숫자 열 `fee_krw`** — 단가 × 시간 × 1.1과 전 행 일치 → 1.1을 빼면 모든 금액이 9% 작게 나옴 → **테스트**로 고정, 담당자에게 "부가세 포함 맞나요?" 확인
2. **자정 넘김** — 야간 예약 38건 → 달력 날짜로 자르면 다음 날로 넘어감 → **질문**: 어느 날짜 소속인가요?
3. **앞자리 0** — `R07`, 사번 `00123` → 숫자로 바꾸면 연결이 깨짐 → **테스트**
4. **취소 반영 여부** — 취소 신청 215건 중 92건은 이미 반영 → 또 빼면 이중 계산 → **질문**: 신청과 확정의 차이는?

## 예상 vs 실제
| 내 예상 | 실제 | 맞음/틀림 |
|---|---|---|
| `fee_krw`는 단가 × 시간과 같다 | 단가 × 시간 × **1.1** | 틀림 → 함정 1 |
| 야간 예약은 다음 날 끝난다 | 38건 전부 다음 날 | 맞음 |
